## [1.2.5] - 2026-10-29

### Changed
- The **n8n webhook** settings (URL, station, API key, test button) moved into a **⚙ Paramètres** dialog.
- The **serial / Bluetooth** settings (port, baud rate, start capture at launch) moved into a **🔌 Connexion** dialog, also reachable by clicking the status badge.
- The main operator view no longer shows the webhook and hardware configuration cards, leaving room for scanning.
- The status badge now reads **● ACTIF** / **○ INACTIF** and opens the connection dialog.

### Added
- The app now writes a standalone **`qr-annulation.svg`** file (22 mm, payload `ANNULER`) next to `scanner_config.json` at startup, ready to import into thermal label software for 50 × 30 mm labels.

### Removed
- The in-app **🖨 Imprimer l'étiquette** button and the generated HTML print page. The app no longer opens a print dialog.

## [1.2.4] - 2026-10-29

### Added
- **Cancel the current entry from the scan station**: a prominent **✕ Annuler la saisie** button, the existing `Esc` shortcut, and a **printable `ANNULER` QR code** all cancel the pending movement without sending anything to n8n.
- The app can print a **50 × 30 mm thermal label** (large QR, line name field, station) to stick on stock lines. The print page opens the browser print dialog automatically.
- `qrcodegen` is now used to render the cancellation QR code in the app and in the printable label.

## [1.2.3] - 2026-10-27

### Changed
- The macOS release is now a **universal binary** (arm64 + x86_64), so it runs on both Apple Silicon and Intel Macs.
- The Intel slice targets macOS 10.14 (Mojave) and the Apple Silicon slice targets macOS 11.0, instead of an Apple Silicon-only build.

## [1.2.2] - 2026-10-26

### Changed
- Disabled the local stock cache and low-stock alerts. `references.csv` is now used only for reference names and descriptions; stock and alerts remain exclusively in Notion. The optional `stock_after` returned by n8n is still displayed as “Stock Notion” after a movement.
- The catalog importer no longer writes `stock`, `stock_en_cours`, or `low_stock` columns. Existing CSV files with these columns remain compatible because the extra columns are ignored.

## [1.2.0] - 2026-10-26

### Added
- **Stock movement mode**: `IN|REF` / `OUT|REF` QR payloads, quantity counted by repeated scans, numeric-keypad override, `Enter` validation, `Esc` cancellation, and automatic validation after 5 seconds of inactivity.
- **Persistent outbox** (`outbox.json`): movements are saved before HTTP and replayed sequentially with exponential backoff, a stable `event_id`, and an `Idempotency-Key` header. The serial thread no longer performs HTTP requests.
- **Webhook contract v2**: `event_id`, `seq`, `sku`, `action`, `qty`, `station_id`, `scanned_at`, `raw`, `motif`, `cancels_event_id`, plus the legacy `barcode`, `timestamp`, and `device_id` fields.
- **Response handling**: `stock_after` updates the local cache; HTTP 409 / `INSUFFICIENT_STOCK` reopens the pending movement with the rejected quantity; 5xx/network errors are retried; business errors are marked rejected.
- **Undo**: 10-second undo window; local removal if the event is still queued, compensating movement with `motif: "Annulation"` if it was already sent.
- **Stock-error correction lock**: after a 409 / `INSUFFICIENT_STOCK`, auto-validation and new scans are paused until the operator adjusts the quantity or cancels, so the rejected movement is not replayed automatically.
- **Local catalog** (`references.csv`): reference name, known stock, and low-stock flag; generated by `scripts/import-notion-csv.py` from the Notion export.
- **QR label generator** (`scripts/generate-labels.py`): A4 HTML sheets with `IN|REF` and `OUT|REF` QR codes, 8 labels per page.
- **Optional API key** sent as `X-Scanner-Key`.
- **Auto-start** option for the serial capture.
- **Chunk splitting**: multiple barcodes in one serial read are processed separately; the 100 ms idle fallback is preserved.
- **4 KPI cards**: movements, validated, pending, rejected.
- **Projected stock** and low-stock warning on the pending movement card.
- **Full-screen toast** on validation/rejection and color-coded status.
- **Atomic config/outbox writes** and a 5,000-line log cap.

### Changed
- The serial thread now only reads and emits scan events; all HTTP work happens in a dedicated sender thread.
- The webhook test payload now includes the v2 fields and `is_test: true`.
- `device_id` is presented as the station identifier; new installs default to the hostname or `POSTE-01`.
- `scanner_config.json` is no longer tracked in git (it contains a real webhook URL). Rotate the webhook and add Header Auth before production.
- The app now requires `references.csv` for names/stock; without it, it still accepts scans but displays the SKU alone.

### Fixed
- Multiple codes in a single serial chunk were previously merged into one payload.
- HTTP responses could update the wrong "last scan" card; the outbox now correlates results with `event_id`.
- The pending state is no longer shown as a permanent red failure.
- Slow n8n responses no longer block the serial reader.
- Logs are bounded instead of growing indefinitely.

## [1.1.0] - 2026-10-20

### Added
- Application icon in dark and light variants (SVG sources, PNG, `.icns` and `.ico` bundles) in `assets/`.
- The app icon now follows the OS appearance at launch on macOS and Windows, and updates live when the system theme changes.
- Window icon loaded from `assets/icon-dark.png` / `assets/icon-light.png`; on macOS the Dock icon is updated as well.
- The UI theme now follows the OS appearance by default (`Auto` mode). The header button cycles `Auto → Dark → Light`, and the choice is persisted.
- macOS packaging script producing a signed `.app` bundle and a DMG (`scripts/package-macos.sh`).
- Windows packaging script producing an NSIS installer (`scripts/package-windows.sh`, `packaging/windows/installer.nsi`).
- Windows executable icon and version metadata embedded via `build.rs` and `winresource`.
- GitHub Actions release workflow building both packages on native runners.

### Changed
- Replaced the boolean `dark_mode` config key with `theme_mode` (`system`, `dark`, `light`). Existing configs without `theme_mode` default to `system`; the old `dark_mode` key is ignored.
- When no local `scanner_config.json` exists, settings are now stored in the user config directory (`~/Library/Application Support/scanner_n8n` on macOS, `%APPDATA%\scanner_n8n` on Windows). The `SCANNER_N8N_CONFIG` environment variable can override the path.

## [1.0.0] - 2026-10-19

### 🎉 Initial Release

First stable release of n8n Scanner — a desktop application to connect a Bluetooth barcode scanner to n8n via webhook.

### Added

#### Graphical User Interface
- Native desktop interface built with [egui](https://github.com/emilk/egui) / eframe 0.29.
- **Dark** (default) and **Light** themes with a built-in toggle.
- Modern slate/indigo color palette with rounded corners.
- KPI Dashboard featuring 3 metrics: Total Scans, n8n Successes, Failures.
- "Last scanned code" card with large monospace display, timestamp, and HTTP status.
- **Copy** button to save the last scanned code to the clipboard.
- Real-time activity log with color-coded levels (Info, Success, Warning, Error, Scan, Raw).
- Auto-scroll toggle for the activity log.

#### Serial Capture
- Auto-detection of available serial ports (macOS: `/dev/cu.*`, Windows: `COMx`).
- Raw chunk reading (512 bytes) with a 50ms timeout.
- 100ms idle timeout for scanners that do not send `\r` or `\n` terminators.
- Explicit activation of **DTR** and **RTS** control lines for maximum compatibility.
- Supported baud rates: 9600, 19200, 38400, 57600, 115200.
- Automatic reconnection upon serial link loss.
- `[RAW]` logs for troubleshooting received bytes.

#### n8n Webhook
- Automatic forwarding of scanned codes to an n8n webhook via HTTP POST (JSON).
- Structured payload: `barcode`, `timestamp` (ISO 8601), `device_id`, `is_test`.
- **"⚡ Test Webhook"** button to validate the connection without scanning.
- Smart detection of test URLs (`/webhook-test/`) with a 1-click assistant to switch to production (`/webhook/`).
- Dynamic URL synchronization: edit the URL in real-time without restarting the capture (via `Arc<RwLock>`).
- 5-second HTTP timeout.

#### Configuration & Persistence
- Automatic saving to `scanner_config.json`.
- Persisted settings: webhook URL, device ID, serial port, baud rate, theme.
- Smart serial port fallback: if the saved port no longer exists (e.g., OS change), automatically defaults to the first available port.

#### Cross-platform
- Native **macOS** build (aarch64-apple-darwin).
- **Windows** x64 cross-compilation (x86_64-pc-windows-gnu via MinGW-w64).
- Added `windows_subsystem = "windows"` attribute in release mode to hide the Windows console.
- Cargo configuration for the MinGW linker (`.cargo/config.toml`).
